# Package Configuration

The `packages/core/package.json` defines how `@nextsparkjs/core` is structured for npm distribution.

## Full Configuration

The manifest is large because it exposes many subpaths. This abridged view
shows the fields relevant to consumers and maintainers:

```json
{
  "name": "@nextsparkjs/core",
  "type": "module",
  "main": "./dist/index.js",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "bin": {
    "update-core": "./scripts/maintenance/update-core.mjs"
  },
  "scripts": {
    "build": "tsup && pnpm build:dts",
    "build:js": "tsup",
    "build:dts": "tsc -p tsconfig.dts.json || echo '⚠️  DTS generation completed with some type errors (partial coverage)'",
    "dev": "tsup --watch",
    "test": "jest",
    "test:node": "npx tsx --test tests/node/*.test.ts",
    "postinstall": "node scripts/postinstall.mjs || true"
  },
  "peerDependencies": {
    "next": ">=15.0.0",
    "react": ">=18.0.0",
    "react-dom": ">=18.0.0"
  }
}
```

## Configuration Explained

### Package Identity

```json
{
  "name": "@nextsparkjs/core",
  "description": "NextSpark - The complete SaaS framework for Next.js"
}
```

- **name**: Scoped npm package (`@nextsparkjs/core`)
- **description**: Package description for npm

### Module System

```json
{
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts"
}
```

- **type**: ES Modules (ESM)
- **main**: JavaScript entry point generated by the build
- **types**: TypeScript declarations generated by the DTS build

### Exports Map

The `exports` field defines subpath imports:

```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./lib/config": {
      "types": "./dist/lib/config/index.d.ts",
      "import": "./dist/lib/config/index.js"
    }
  }
}
```

**Usage Examples:**

```typescript
// Main export
import { cn } from '@nextsparkjs/core'

// Config utilities
import { defineConfig } from '@nextsparkjs/core/lib/config'

// Components
import { Button } from '@nextsparkjs/core/components/ui/button'

// Hooks
import { useAuth } from '@nextsparkjs/core/hooks/useAuth'
```

### CLI Binary

The `nextspark` executable is shipped by the separate `@nextsparkjs/cli`
package, not by `@nextsparkjs/core`:

```json
{
  "name": "@nextsparkjs/cli",
  "bin": {
    "nextspark": "./bin/nextspark.js"
  }
}
```

After installation, the CLI is available:

```bash
pnpm exec nextspark --help
pnpm exec nextspark init --help
```

### Build Scripts

```json
{
  "scripts": {
    "build": "tsup && pnpm build:dts",
    "build:js": "tsup",
    "build:dts": "tsc -p tsconfig.dts.json || echo '⚠️  DTS generation completed with some type errors (partial coverage)'",
    "postinstall": "node scripts/postinstall.mjs || true"
  }
}
```

- **build**: Build JavaScript and then generate declarations
- **build:js**: Build JavaScript only
- **build:dts**: Generate declarations; the current script permits partial DTS output
- **postinstall**: Run the package's best-effort setup hook after installation

### Peer Dependencies

```json
{
  "peerDependencies": {
    "next": ">=15.0.0",
    "react": ">=18.0.0",
    "react-dom": ">=18.0.0"
  }
}
```

Users must have these installed in their project.
