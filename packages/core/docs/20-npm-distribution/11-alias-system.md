# Alias System - Dual-Mode Path Resolution

> **Registry commands in this guide** run in a generated project, from its root. In the NextSpark monorepo, run `cd apps/dev && node ../../packages/core/scripts/build/registry.mjs` (add `--watch` to watch).

This document explains the core innovation that makes `@nextsparkjs/core` work both as a monorepo package and as an npm package.

## The Problem

The package needs to import registries that are:
1. **Not bundled** with the package (they're project-specific)
2. **Generated by `nextspark init`, `nextspark build`, or an explicit registry command**
3. **Located in the application's `.nextspark/registries/` directory**

```typescript
// This import exists in compiled package code
import { ENTITY_REGISTRY } from '@nextsparkjs/registries/entity-registry'

// But the actual file is in:
// - Monorepo app: apps/dev/.nextspark/registries/entity-registry.ts
// - NPM Mode: .nextspark/registries/entity-registry.ts
```

## The Solution: External Imports + Alias Resolution

### Step 1: Mark Registry Imports as External (tsup)

In `tsup.config.ts`:

```typescript
export default defineConfig({
  // Package modules are transpiled without bundling, so project registry
  // imports remain available for the consuming application to resolve.
  bundle: false,
  // ...
})
```

This means when the package is built, imports like:
```typescript
import { ENTITY_REGISTRY } from '@nextsparkjs/registries/entity-registry'
```

Are **kept as-is** in the compiled output, not resolved at build time.

### Step 2: Package Source Uses @nextsparkjs/registries/*

Package source that needs generated registries imports from `@nextsparkjs/registries/*`:

```typescript
// In packages/core/src/lib/services/permission.service.ts
import { AVAILABLE_ROLES } from '@nextsparkjs/registries/permissions-registry'
```

### Step 3: Consumer Project Resolves the Alias

The consumer project configures THREE resolution layers:

#### A. TypeScript Resolution (tsconfig.json)

Generated projects include these aliases in `tsconfig.json`:

```json
{
  "compilerOptions": {
    "paths": {
      "@nextsparkjs/registries/*": ["./.nextspark/registries/*"],
      "@nextsparkjs/core/*": ["./node_modules/@nextsparkjs/core/dist/*"]
    }
  },
  "include": [".nextspark/**/*.ts"]
}
```

#### B. Turbopack Resolution (next.config.mjs)

For Next.js 15 or 16 with Turbopack:

```typescript
const nextConfig: NextConfig = {
  turbopack: {
    resolveAlias: {
      '@nextsparkjs/registries': './.nextspark/registries',
    }
  },
  // ...
}
```

#### C. Webpack Resolution (next.config.mjs)

For production builds or if using webpack:

```typescript
const nextConfig: NextConfig = {
  webpack: (config) => {
    config.resolve.alias = {
      ...config.resolve.alias,
      '@nextsparkjs/registries': path.resolve(__dirname, '.nextspark/registries'),
    }
    return config
  },
}
```

## Registry Generation

The registries in `.nextspark/registries/` are generated by `scripts/build/registry.mjs`:

### How Generation Detects Mode

```javascript
// scripts/build/registry/config.mjs

export function getConfig(projectRoot = null) {
  const root = projectRoot || detectProjectRoot()

  // Check if running in npm mode
  const isNpmMode = isInstalledAsPackage(root)

  // Both modes write into the application project.
  const outputDir = join(root, '.nextspark/registries')

  return { projectRoot: root, isNpmMode, outputDir, ... }
}
```

### Import Path Conversion

Generated registries use `convertCorePath()` for their imports:

```javascript
// scripts/build/registry/config.mjs

export function convertCorePath(importPath, outputFilePath, config) {
  // In monorepo mode, keep @/core/ aliases
  if (!config.isNpmMode) {
    return importPath  // e.g., '@/core/lib/permissions/types'
  }

  // In NPM mode, convert to package import
  if (importPath.startsWith('@/core/')) {
    const relativePart = importPath.replace('@/core/', '')
    return `@nextsparkjs/core/${relativePart}`  // e.g., '@nextsparkjs/core/lib/permissions/types'
  }

  return importPath
}
```

**Example generated registry:**

```typescript
// .nextspark/registries/permissions-registry.ts (NPM mode)

// Import from the package (resolved by bundler)
import { CORE_PERMISSIONS_CONFIG } from '@nextsparkjs/core/lib/permissions/system'

// Import from consumer's theme (resolved by @/ alias)
import { PERMISSIONS_CONFIG_OVERRIDES } from '@/contents/themes/default/config/permissions.config'
```

## TSConfig Auto-Generation

The `update-tsconfig.mjs` script automatically adds aliases in NPM mode:

```javascript
// scripts/build/update-tsconfig.mjs

if (isNpmPackage) {
  baseConfig.compilerOptions.paths = baseConfig.compilerOptions.paths || {}

  // Registry alias
  baseConfig.compilerOptions.paths['@nextsparkjs/registries/*'] = ['./.nextspark/registries/*']

  // Core package alias
  baseConfig.compilerOptions.paths['@nextsparkjs/core/*'] = ['./node_modules/@nextsparkjs/core/dist/*']

  // Include .nextspark folder
  baseConfig.include.push('.nextspark/**/*.ts')
}
```

## Comparison: Monorepo vs NPM Mode

| Aspect | Monorepo Mode | NPM Mode |
|--------|--------------|----------|
| Registry location | `apps/dev/.nextspark/registries/` | `.nextspark/registries/` |
| @/core/ imports | Resolved via tsconfig | Converted to @nextsparkjs/core/ |
| @/contents/ imports | Works directly | Works directly |
| Generated at | Explicit registry build, or before a CLI build | During init and explicit registry/build commands |
| tsconfig.json | Checked in for `apps/dev` | Generated by the wizard; refreshable with `update-tsconfig.mjs` |

## Debugging

### Check if Alias is Working

Add to next.config.ts temporarily:

```typescript
webpack: (config) => {
  console.log('Aliases:', config.resolve.alias)
  return config
}
```

### Verify Registry Exists

```bash
ls -la .nextspark/registries/
```

Should show:
```
entity-registry.ts
template-registry.ts
template-registry.client.ts
permissions-registry.ts
plugin-registry.ts
theme-registry.ts
...
```

### Check Import in Compiled Package

```bash
grep -r "@nextsparkjs/registries" node_modules/@nextsparkjs/core/dist/
```

Should show external imports preserved.

## Common Issues

### "Cannot find module '@nextsparkjs/registries/...'"

1. Registries not generated:
   ```bash
   pnpm build:registries
   ```

2. Missing Turbopack alias - check `next.config.mjs`

3. tsconfig.json not updated - regenerate:
   ```bash
   node node_modules/@nextsparkjs/core/scripts/build/update-tsconfig.mjs
   ```

### "Module '@nextsparkjs/core/...' not found"

1. Package not built:
   ```bash
   cd packages/core && pnpm build
   ```

2. Missing transpilePackages:
   ```typescript
   transpilePackages: ['@nextsparkjs/core']
   ```
