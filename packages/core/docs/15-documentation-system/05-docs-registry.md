# Documentation Registry

## Introduction

The **Docs Registry** is an auto-generated TypeScript module containing metadata for the active theme's public and superadmin documentation. It is generated by `generateDocsRegistry()` in `packages/core/scripts/build/registry/generators/docs-registry.mjs`, which is invoked by `packages/core/scripts/build/registry.mjs` with the other registry generators.

**Generated location:** `<project>/.nextspark/registries/docs-registry.ts`
**Monorepo location:** `apps/dev/.nextspark/registries/docs-registry.ts`
**Import:** `@nextsparkjs/registries/docs-registry`

## Documentation Structure

Only the active theme is scanned. `NEXT_PUBLIC_ACTIVE_THEME` selects the theme; when it is not set, the registry build stops with an environment error instead of generating anything.

```text
themes/[active-theme]/docs/
├── public/
│   └── 01-getting-started/
│       └── 01-introduction.md
└── superadmin/
    └── 01-setup/
        └── 01-configuration.md
```

The `public` tree produces `/docs/[section]/[page]` entries. The `superadmin` tree produces `/superadmin/docs/[section]/[page]` entries. Core and plugin documentation are internal reference material and are not registry sources.

## Registry Structure

### TypeScript Interfaces

```typescript
export interface DocPageMeta {
  slug: string
  title: string
  order: number
  path: string
  source: 'public' | 'superadmin'
}

export interface DocSectionMeta {
  slug: string
  title: string
  order: number
  pages: DocPageMeta[]
  source: 'public' | 'superadmin'
}

export interface DocsRegistryStructure {
  public: DocSectionMeta[]
  superadmin: DocSectionMeta[]
  all: DocSectionMeta[]
}
```

### Registry Constant

`DOCS_REGISTRY` groups public and superadmin sections separately. Its `all` collection merges both groups and sorts them by section order.

```typescript
import { DOCS_REGISTRY } from '@nextsparkjs/registries/docs-registry'

const publicSections = DOCS_REGISTRY.public
const superadminSections = DOCS_REGISTRY.superadmin
const allSections = DOCS_REGISTRY.all
```

## Helper Functions

The generated module exports these helpers:

- `getAllDocSections()`
- `getPublicDocSections()`
- `getSuperadminDocSections()`
- `findDocSection(slug)`
- `findDocSectionInCategory(slug, category)`
- `findDocPage(sectionSlug, pageSlug)`

```typescript
import { findDocPage } from '@nextsparkjs/registries/docs-registry'

const page = findDocPage('getting-started', 'introduction')
```

## Build Process

`packages/core/scripts/build/registry.mjs` generates the docs registry with every other registry. From this monorepo's repository root, regenerate them with:

```bash
cd apps/dev && node ../../packages/core/scripts/build/registry.mjs
```

The registry watcher observes `CONFIG.pluginsDir`, `<contentsDir>/entities`, `CONFIG.themesDir`, and `<contentsDir>/config`.

## Discovery Algorithm

For the active theme, the generator:

1. reads `docs/public/` into `DOCS_REGISTRY.public`;
2. reads `docs/superadmin/` into `DOCS_REGISTRY.superadmin`;
3. orders sections and pages by their numeric filename prefixes;
4. stores markdown paths relative to the consuming project's working directory; and
5. creates `DOCS_REGISTRY.all` from both collections.

## Accessing the Registry

Use the package alias in server components, client components, layouts, and route handlers:

```typescript
import { DOCS_REGISTRY, findDocPage } from '@nextsparkjs/registries/docs-registry'

const section = DOCS_REGISTRY.public.find(item => item.slug === sectionSlug)
const page = findDocPage(sectionSlug, pageSlug)
```

Select `DOCS_REGISTRY.public` for public documentation and `DOCS_REGISTRY.superadmin` for superadmin documentation.

## Navigation Generation

Documentation components render sidebars and breadcrumbs from registry metadata. Public links use `/docs/[section]/[page]`; superadmin links use `/superadmin/docs/[section]/[page]`.

## Troubleshooting

### Registry Not Updating

Confirm that the markdown file is inside the active theme's `docs/public/` or `docs/superadmin/` directory and follows the `{order}-{slug}.md` convention. Then regenerate all registries:

```bash
cd apps/dev && node ../../packages/core/scripts/build/registry.mjs
```

### Missing Documentation

Check that the section directory follows `{order}-{slug}/`, that the page follows `{order}-{slug}.md`, and that it is under the active theme's public or superadmin documentation directory.

### Import Errors

Import the generated module through `@nextsparkjs/registries/docs-registry`. Confirm that the consuming project's `.nextspark/registries/docs-registry.ts` file exists after the registry build.
